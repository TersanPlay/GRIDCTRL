# Exemplos de prompts — GRIDCTRL

## 1. Planejar sistema novo
Use a Skill GRIDCTRL em DISCOVER + PLAN. Descreva arquitetura de informação, componentes, design tokens e uma identidade `industrial` baseada no grid técnico. Não implemente antes de revisar dependências e definir estados de interface.

## 2. Redesenhar dashboard existente
Use GRIDCTRL em AUDIT → PLAN → BUILD → VALIDATE. Audite rotas, componentes, APIs, autenticação, permissões e regras de negócio. Preserve as funções existentes. Adote `warm-editorial` com `stableId=dashboard-v2`. Não permita posicionamento aleatório. Produza diff e testes efetivos.

## 3. Adaptação pastel
Use GRIDCTRL com `variantId=soft-pastel` e `stableId=portfolio-v1`. Deixe decoração geométrica em camada não interativa. Separe cores de identidade dos tokens de erro, aviso, sucesso e foco; valide contraste de todo texto e controle.

## 4. Performance de hero futurista
Crie um hero inspirado no grid técnico GRIDCTRL. Use CSS/SVG no lugar de WebGL se não houver necessidade real de 3D interativo. Suporte prefers-reduced-motion. Priorize LCP/CLS e explique os custos de recursos carregados.

## 5. Conferir fidelidade visual
Use GRIDCTRL em VALIDATE. Compare a implementação com os arquivos de referência. Avalie proporções, linhas, tipografia, densidade, alinhamento, estados e reflow em 320/390/768/1440 px quando possível. Reprove soluções que apenas acrescentem cor laranja e sombras genéricas.

## 6. Integração gradual
Antes de modificar qualquer componente real, liste arquivos afetados, funcionalidades preservadas, riscos, plano incremental, testes existentes e possíveis regressões. Não altere backend nem regras não relacionadas.

## 7. Paletas em tempo real
Use a Skill GRIDCTRL para adicionar um seletor de paletas estável ao meu aplicativo, com seis opções (`industrial`, `soft-pastel`, `warm-editorial`, `mint-lab`, `lilac-lab`, `midnight`). A prévia deve atualizar imediatamente sem alterar ordem nem posição dos componentes. Persistir preferência local e aplicar tokens funcionais de foco/erro/aviso/sucesso.

## 8. Uso de shadcn/ui
Audite meu projeto React antes de implementar. Utilize shadcn/ui para Button, Card, Tabs, Dialog, Accordion e Switch conforme a versão compatível com minha stack. Não entregue controles com aparência nativa crua do navegador. Preserve HTML semântico, teclado, labels, foco e regras existentes.
